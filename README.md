# Damar Galih Subiyanto — Portfolio

A light-editorial, recruiter-facing portfolio for a Junior Web Developer / Frontend Developer with additional data analysis skills. Built with React 19, Tailwind CSS v4, Framer Motion and TanStack Start (SSR), rendered by Nitro, and ready to deploy to Cloudflare Workers.

All displayed content is based on the CV in `src/data/portfolio.ts`. No invented experience, projects, metrics or URLs.

## Overview

- `/` — single-page portfolio with anchor navigation: About, Services, Projects, Experience, Education, Certifications and Contact.
- `/cv` — print-friendly resume generated from the same data; use the browser print dialog to save as PDF.
- SSR with an error boundary, `sitemap.xml`, `robots.txt`, canonical URLs, Open Graph metadata and JSON-LD `Person`.
- Contact uses a glass contact form that composes a `mailto:` draft (no backend, no data stored) plus direct email, LinkedIn, Instagram and GitHub links.
- Social links (LinkedIn, Instagram, GitHub) appear as a centered icon row at the end of the photo-free hero, plus in the contact section, footer and CV header; all URLs come from `PROFILE` in `src/data/portfolio.ts`. The portrait is shown in About.
- Visual system: light editorial by default with a working dark mode toggle in the centered floating pill navbar. Light uses a white/`#F7F8FA` canvas and `#111111` ink; dark is monochrome — pure white text on a true `#000000` canvas with white primary buttons. Inter bold headlines, Cormorant Garamond italic accents, restrained Framer Motion for card entrances/hover and Lenis for smooth scrolling (Motion was chosen over GSAP to keep this small project lean), responsive mobile-first layout. Theme choice is stored in `localStorage` and applied before paint; the first visit follows the system preference.

## Commands

Bun is the package manager of record.

```sh
bun install
bun run dev          # local dev server
bun run lint
bun run typecheck
bun run test
bun run check        # lint -> typecheck -> test -> build
```

`npm run dev -- --host 0.0.0.0 --port 8081` also works for local preview when Bun is unavailable. If `bun` is not on PATH, `npx bun <command>` runs the pinned Bun version and keeps `bun.lock` in sync.

## Environment Variables

| Variable                          | Scope               | Required | Purpose                                                                                                           |
| --------------------------------- | ------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `VITE_SITE_URL`                   | Client (build-time) | No       | Production domain for canonical, OG, JSON-LD, sitemap and robots. Default: `https://portofoliodamar.lovable.app`. |
| `VITE_CLOUDFLARE_ANALYTICS_TOKEN` | Client (build-time) | No       | Public Web Analytics token. The beacon is not loaded when empty.                                                  |

Set `VITE_SITE_URL` to the final URL before sharing the portfolio link with recruiters, then rebuild/redeploy so all metadata follows it.

## Build & Deployment

```sh
bun run build
bunx wrangler deploy
```

Build output:

- `.output/public/` — static assets.
- `.output/server/` — Nitro bundle for Cloudflare Workers.
- `.output/server/wrangler.json` — generated Wrangler config.

`bun run preview` uses `nitro preview` (requires `npx wrangler`); `vite preview` is not used because SSR output lives in `.output/`, not `dist/`. Deploy from the repository root. Wrangler reads `.wrangler/deploy/config.json`, which points to the generated Nitro config — change Nitro/Vite config instead of that generated file.

## Editing Content

Change `src/data/portfolio.ts` only. Sections, CV and structured data all read from it. Do not add skills, experience, projects or links that are not on the CV.

`PROFILE.avatar` points to `/images/profile.webp`, an optimized version of the owner-supplied photo (the large PNG original is kept locally but git-ignored); `ProfileImage` falls back to a serif monogram if the file is missing, so the page never shows a broken image. `PROFILE.linkedin`, `PROFILE.instagram` and `PROFILE.github` hold the owner-supplied social URLs and are reused across the page, the CV and JSON-LD `sameAs`. See `docs/DESIGN-SYSTEM.md` for the UI structure, component hierarchy and Tailwind styling system.
